name: Launch strategy
description: Product wedge, truthful positioning, and publication boundary
type: project
---

**Wedge:** “DevTrack writes your standup update when you commit.” Lead with outcome, not platform breadth or “AI-powered.”

**Positioning:** local-first, no account required, pending queue, and silent daemon. Under 60 seconds is a target; do not state it as measured fact without current evidence.

**Parity:** Azure DevOps, GitHub, GitLab, and Jira parity is an invariant, but executable docs must disclose current connector gaps. Do not claim parity is achieved or normalize a staged rollout without explicit user approval. A demo may use one connector for clarity.

**Decision filter:** serves the wedge → protects local-first/trust → reduces time-to-value → supported by user evidence.

Publishing posts, directory submissions, uploads, and external PR changes is a separate explicit action requiring authorization and an authenticated owner session.
