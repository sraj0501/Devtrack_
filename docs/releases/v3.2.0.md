# DevTrack v3.2.0

DevTrack v3.2.0 adds DevTrack Sage: a local, cross-harness command-knowledge system that turns
privacy-minimized development activity into deterministic, searchable Markdown. This release also
ships deterministic ticket mapping, silent work-time inference, the rolling development update
channel, and the corrected native-Git path.

## Highlights

- Capture useful command activity from Codex, Claude Code, GitHub Copilot CLI, OpenCode, Cursor,
  and Devin through independently managed, additive adapters.
- Distill a durable SQLite queue into deterministic Markdown without sending raw harness payloads
  to PostgreSQL, telemetry, MCP, or remote synchronization.
- Search, list, route, merge, repair, import, export, retain, and safely delete Sage knowledge with
  bounded local operations and explicit confirmation for destructive actions.
- Read current Sage knowledge and bounded pipeline diagnostics through four additional read-only
  MCP tools, bringing the local MCP server to ten tools.
- Resolve branch-to-ticket mappings with deterministic workspace rules, stored provenance, and an
  immutable correction audit.
- Infer bounded work sessions silently from local activity while preserving explicit corrections.
- Select the stable or rolling development update channel with `devtrack upgrade --main` and
  `devtrack upgrade --dev`.

## Fixed

- Normal Git commands are no longer routed through the interactive DevTrack commit enhancer.
  Generated observation hooks remain silent and fail-open, and explicit enhanced commits return
  immediately after Git succeeds.
- Database schema initialization now batches migrations transactionally.
- Windows and Linux restart persistence, no-send behavior, and packaged native MCP execution have
  expanded automated coverage.

## Privacy and compatibility

- Sage stores raw capture data only in bounded local spool/SQLite paths and publishes portable
  Markdown locally. Its MCP surface exposes published knowledge and bounded status, never prompts,
  output, reasoning, raw events, logs, or adapter configuration paths.
- Existing v3.1.x configuration and SQLite data remain supported. The Go client remains usable
  offline; managed Python features still require PostgreSQL and an explicitly configured service.
- The separate TASK-154 server-admin visual redesign is deferred and is not included in v3.2.0.
- The optional communication-learning HTTP adapters remain a known limitation; automatic local
  Git-history voice seeding uses the separate managed onboarding path.
