Ten-minute quick start

1. Install

Download the matching GitHub Release asset: `.tar.gz` for Linux/macOS or the direct `devtrack_windows_amd64.exe` for Windows.

2. Configure

devtrack setup
devtrack doctor

Managed mode writes its environment immediately and bootstraps the Python server and local model in the background. PostgreSQL is required for that server. Lightweight mode keeps only the Go-native surface.

3. Get local value immediately

devtrack mcp setup
devtrack mcp test
devtrack start
devtrack status

4. Use a ticket branch and commit normally

git switch -c feature/PROJ-123-description
git commit -m "PROJ-123: implement the change"
devtrack queue list
devtrack work report

The core loop

  1. The Go daemon detects a commit.
  2. Ticket context is resolved from branch, commit prefix, trailer, explicit work session, or recent context.
  3. The configured LLM enriches the raw signal when available; failure falls back safely.
  4. Any external action is staged with confidence.
  5. The developer can approve, edit, reject, or correct it without interrupting Git.
  6. Corrections become local learning evidence.
An unlinked commit is logged and included in local history. It never blocks the developer.

Interactive commit wrapper

devtrack git commit is an optional interactive workflow with message refinement, ticket selection, time capture, and a push offer. It is separate from silent daemon observation.

Pending actions

The queue is the trust primitive. There is no direct-send fallback for PM, email, or Git writes.

devtrack queue
devtrack queue list
devtrack queue status
devtrack queue approve <id>
devtrack queue edit <id> '<json>'
devtrack queue reject <id>
devtrack queue flag <id> "correction"

Every action includes its type, target, content, confidence, expiry, and state. CLI and supported notification channels provide corrections without making the TUI mandatory.

EOD reports and voice

devtrack work start PROJ-123
devtrack work status
devtrack work report
devtrack eod generate
devtrack eod show

devtrack voice status
devtrack voice seed
devtrack voice profile
devtrack voice add --context report "example text"

The server generates narratives using the local evidence profile and relevant examples when available. Without a usable profile or provider, DevTrack degrades to factual template/raw output.

On first managed use, the onboarding worker can seed enabled local Git workspaces after the server becomes ready. External mode does not automatically upload local learning data.

MCP context

The Go-native MCP server uses JSON-RPC 2.0 over stdio and reads local SQLite. It does not require Python, PostgreSQL, Ollama, or a network request.

devtrack mcp setup
devtrack mcp status
devtrack mcp test
devtrack mcp serve

Six read-only tools expose active work, recent activity, pending actions, ticket context, work history, and the EOD roll-up. MCP does not bypass the pending-actions boundary.

Architecture

devtrack_client (Go)                    devtrack_server (Python)
local SQLite                            PostgreSQL (required)
daemon, queue, MCP        HTTPS JSON    LLM, reports, voice, admin
connectors, alerts, TUI  ------------> webhook_server.py
  • The Go client never connects to PostgreSQL.
  • The Python server does not read Go-owned SQLite tables in PostgreSQL mode.
  • New client/server messages use authenticated HTTP/JSON.
  • Go owns PM connectors, alerts, Telegram, MCP, and git-sage.
  • Python owns LLM enrichment, reports, personalization, boardroom, and administration.

Troubleshooting

devtrack status
devtrack doctor
devtrack settings
devtrack logs -f

Managed bootstrap failed

Use devtrack doctor --repair. The worker is idempotent and reports its state and log path.

PostgreSQL unavailable

The Python server requires a reachable postgresql:// URL with a database name. There is no server SQLite fallback.

Ollama unavailable

Check curl "$OLLAMA_HOST/api/tags". Increase long/LLM timeouts for a healthy slow model; provider failure must not block Git.

No staged action

Confirm the branch or commit resolves a ticket ID, then follow devtrack logs -f. Use devtrack queue or queue list.

Need help

Open a GitHub issue with version, OS, mode, redacted doctor output, and a minimal log excerpt. Never include tokens or private code.

Vision and roadmap

You write code. DevTrack handles the rest—silently, accurately, in your voice, getting better every day.

Non-negotiables

  • No prompts in the daemon's main flow.
  • Everything outbound is staged first.
  • Confidence is explicit.
  • Learning is local and evidence-led.
  • Failures never block Git.
  • The daemon is the product; interfaces provide visibility.

Current phase

Phases 0–8 and the PostgreSQL server epic are complete. Phase 9 is the adoption gate: package the existing product so a stranger reaches a staged action, an EOD preview, and MCP context in under ten minutes.

The remaining planned Phase 9 item is TASK-124, evidence-backed launch drafts. It is launch packaging, not a missing product capability.
